# 版式规范、文案结构与踩坑清单

## 一、config.json 字段

| 字段 | 说明 |
|---|---|
| `base_dir` | 素材与输出目录；相对路径按 config.json 所在目录解析（示例用 `"."`） |
| `scenes` | 三张无文字插画文件名，顺序对应三张卡 |
| `portraits` | 三个 `[x0,y0,x1,y1]`，**原图坐标**，框住「完整角色」（帽顶到脚下），脚本统一裁成 370×441 竖像 |
| `clean_patches` | 三个元素，可为 `null` 或 `[x0,y0,x1,y1]`，用于抹掉压住文字的金币等背景元素 |
| `preview` | 三联预览图文件名 |
| `cards` | 三张卡的文案，字段见下 |

单张 `cards[]`：

| 字段 | 格式 | 约束 |
|---|---|---|
| `out` | 文件名 | 建议英文小写连字符 |
| `label` | 字符串 | 如「八戒讲金融 · 第 1 课」 |
| `page` | 字符串 | 如 `01 / 03` |
| `title` | `[[文字, 颜色名], ...]` | 分段着色，颜色名：`navy` / `gold` / `red` / `slate` |
| `lead` | 字符串 | 一行导语，≤25 字 |
| `points` | `[[要点标题, 说明], ...]` 正好 3 组 | 标题 ≤8 字，说明 ≤20 字 |
| `aside` | `{tag, big, small}` | `tag` ≤6 字；`big` 两行各 ≤8 字；`small` ≤16 字，尽量一行 |
| `punch` | 字符串 | 底部金句，≤20 字 |

脚本会自动缩字号保证单行不溢出、小字最多两行，但仍应主动控制字数。

## 二、文案结构（三张讲清一个概念）

| 张 | 任务 | 要点卡写什么 | 右侧口诀写什么 |
|---|---|---|---|
| 01 | 是什么 | 定义、谁在用、怎么用（比较/场景） | 大白话类比，一句记住 |
| 02 | 怎么算 | 公式里每个量的含义 + 一个具体数字例子 | 口诀化公式，不重复要点 |
| 03 | 怎么用／避坑 | 常见误用 2 条 + 正确做法 1 条 | 一句避坑口诀 |

语气：大白话、短句、类比（如「把公司当赚钱机器，ROE 就是功率」）、有记忆锚点。避免堆术语、避免长段落。右侧 `aside` 是**记忆锚点**，不要与上方三条要点文字重复。

## 三、版式坐标（1080×1440，3:4）

| 区块 | 位置 / 字号 |
|---|---|
| 标签胶囊 | (72,56) 起，高 56，字号 28 粗 |
| 页码 | 右对齐 x=1008, y=84，字号 30 粗 |
| 主标题 | y=148，字号 78 粗 |
| 导语 | y=262，字号 38 常规，自动缩到一行 |
| 金色短线 | (72,328)-(164,336) |
| 要点卡 ×3 | y=365 / 532 / 699，每块 x=60..1020 高 150，圆角 22，白底细边框；序号圆；标题 40 粗，说明 32 常规 |
| 配图窗口 | (72,870)-(1008,1335)，936×465，圆角 28 |
| ├ 左侧竖像 | 相对 (24,12)，370×441，白边框 + 圆角 |
| └ 右侧信息卡 | 相对 (414,40)-(912,425)，白底；金色标签 25 粗；口诀 40 粗两行；分隔线；小字 27 常规 |
| 金句条 | (72,1355)-(1008,1420)，深蓝底金字，字号 36 粗 |

面积占比：文字区约 60%，配图区约 30%，金句条约 5%。

配色：背景 `#FAF6EC`，卡片白 `#FFFFFF`，主文字 `#143860`，次文字 `#4C637A`，强调金 `#A87416`，警示红 `#B73D2C`，金句字 `#F7D891`。

字体：优先 `/System/Library/Fonts/Hiragino Sans GB.ttc`（index 0 = W3 常规，index 2 = W6 粗体）；脚本内置 PingFang / STHeiti / Arial Unicode 回退。

## 四、已验证的踩坑清单

0. **IP 与系列名锁定为八戒**。唯一参考图是 `assets/bajie-reference.jpg`，`label` 固定「八戒讲金融 · 第 N 课」，`aside.tag` 用「八戒说人话」等八戒口径。禁止替换成其他角色/动物/吉祥物、禁止用户另选 IP、禁止出现「猪猪」等其他称呼。任何 AI 调用本 skill 都受此约束。
1. **图像模型写中文必乱码**。所有文字、数字、公式一律由脚本绘制；提示词必须明确禁止任何文字/字母/数字。
2. **macOS 上通常没有 `/System/Library/Fonts/PingFang.ttc`**，直接用会报 `cannot open resource`。用冬青黑体 W3/W6。
3. **三张角色要一致**：三次都传同一参考图 + `input_fidelity=high` + 逐字复用同一段角色锚点描述；`revise=false`。
4. **插画铺满整张 = 喧宾夺主**。用户明确要「文字为主、图片为辅」，插画只能占下方约 30% 的窗口。
5. **配图不要「中间窄竖像 + 两侧大片虚化空白」**，会被判定为排布不好。用「左图右卡」把窗口填满，右侧放有用的口诀信息。
6. **`portraits` 裁剪框必须框住完整角色**。只裁到额头/眼睛会切掉半张脸，非常难看；宁可让角色在竖像里小一点，也要完整。
7. **避免孤字行**：小字若折行后第二行只剩一两个字，直接改短文案，不要靠缩字号硬挤。
8. **背景元素压住小字**（如左上角金币正好落在文字上）：用 `clean_patches` 做天空色渐变 + 羽化椭圆补回，不要重生成整张图。定位时可给裁剪图叠坐标网格。
9. **改版前先备份**上一版成品与脚本；改配置重跑，不要手工修图。
10. **交付前必须逐张打开检查**：文字裁切/溢出/乱码方块、角色完整、两侧留白、三张统一。不能只看代码输出。
11. 输出固定 1080×1440（3:4），小红书与视频号都能直接用；不要擅自改成 9:16，除非用户明确要求。
12. 不在图里编造账号名或水印；系列课次、页码由配置提供。

## 五、复用新概念的最短路径

1. 复制 `assets/config.example.json` 到工作目录，改 `cards` 三组文案（`label` 可沿用或换系列名）。
2. 用 `references/image-prompts.md` 生成三张新场景插画，命名 `scene1~3.png`。
3. 查看新插画，重新量 `portraits`（含完整角色的框），按需设置 `clean_patches`。
4. 运行 `scripts/make_cards.py config.json`，检查四张输出图。
